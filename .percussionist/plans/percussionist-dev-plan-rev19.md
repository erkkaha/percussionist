# Plan: beatctl correctness — project defaults ignored on submit, `-n` silently overrides file namespaces, wrong wait exit codes, dead board flags

**Task:** `percussionist-dev-plan-rev19`

Five confirmed CLI bugs in `packages/cli/src`, all user-visible and each with a cheap, surgical fix:

1. `submit` advertises "Merge project defaults first" (`submit.ts:78-80`) but only `model`/secrets/git/`sidecars`/`initScript` are actually merged. `spec.agent`, `spec.image`, `spec.timeoutSeconds`, `spec.resources` are never taken from the Project — a project configured with `--agent builder` submits agent-less runs, and on capability-gated flows the dispatcher withholds the completion tool (`mcp-server.ts:887-971` gates `complete_*` on `run.complete.*` capabilities of `spec.agent`) so the run dies with "session ended without completion signal" (`polling.ts:1177`).
2. `submit -f` / `project create -f` unconditionally overwrite the file's `metadata.namespace` (`submit.ts:211-213`, `project.ts:115-117`) because `-n` carries a commander **default** (`index.ts:91`, `index.ts:391`), so `opts.namespace` is never falsy. A YAML with `namespace: my-ns` submitted without `-n` silently lands in the `percussionist` default namespace.
3. `beatctl wait` breaks its own documented exit-code contract (`wait.ts:9-13`): a 404 on the **first** poll (typo'd name) exits 1 with "was deleted before settling" (`wait.ts:81-93`) instead of exit 3 "CR not found". In the CI pattern `submit && wait`, usage errors masquerade as run failures.
4. Dead board surface: `board task move` patches `status.column` (`board.ts:217`), which the same file documents as legacy that "controllers stopped writing" (`board.ts:82-87`) — the command prints success and changes nothing. `board task add --column` (default `ready`, `index.ts:493`) is parsed and never read (`board.ts:144-198`). README.md:481 still documents `move`.
5. `--agent-name` pairs with `--agent-file` by array index (`submit.ts:110`), not "the preceding `--agent-file`" as the help text claims (`index.ts:126-129`).

Explicitly **out of scope** (tracked separately): the `beatctl auth web-token` Secret-wipe issue (secret updates destroying sibling keys).

## Context

Relevant existing code (all paths relative to repo root):

- **`packages/cli/src/submit.ts`** — `buildRunFromFlags(opts, projectDefaults)` hand-rolls the Project-default merge. Line 80: `const resolvedAgent = opts.agent;` (no `?? pd?.agent`). Lines 135-136 use `opts.image` / `opts.timeout` directly, never falling back to `pd?.image` / `pd?.timeoutSeconds`; `pd?.resources` is not merged at all (though `pd.sidecars` at 176 and `pd.initScript` at 178 are). `buildRunFromFile(path, opts)` at 207-219 overwrites `metadata.namespace` whenever `opts.namespace` is truthy — which it always is due to the commander default. `runSubmit` (258-333) computes `ns = opts.namespace ?? DEFAULT_NAMESPACE` **before** reading the file, so with `-f` and no `-n` the Project lookup (`getProject(custom, ns, opts.project)` at 272) targets the default namespace even when the file names another.
- **`packages/cli/src/index.ts`** — `submit` `-n` option at line 91 and `project create` `-n` at line 391 both pass `DEFAULT_NAMESPACE` as commander's static default; since `@percussionist/kube`'s `NAMESPACE` honors `$PERCUSSIONIST_NAMESPACE` (`packages/kube/src/index.ts:177`) but the commander default is a fixed string, the default also silently disables the documented env-var override for these two commands. `--agent-name` help at 126-129 claims "preceding --agent-file" semantics. `board task add --column` at line 493.
- **`packages/cli/src/project.ts`** — `buildProjectFromFile` (112-119) same unconditional namespace overwrite; `runProjectCreate` (121-143) already falls back correctly (`project.metadata.namespace ?? DEFAULT_NAMESPACE` at 128).
- **`packages/cli/src/wait.ts`** — `runWait` polls `getRun` at ~1 Hz. The 404 branch (81-93) always exits 1 "was deleted before settling", regardless of whether the run was ever observed. Documented contract at 8-13: 0 = awaited phase, 1 = other terminal, 2 = timeout, 3 = transient/CR-not-found. The function calls `process.exit` directly, which makes it untestable in-process.
- **`packages/cli/src/board.ts`** — `runBoardTaskMove` (209-222) patches `{ column: opts.to }` via `patchTaskStatus` and ignores `projectName`. `runBoardTaskAdd` (144-198) accepts `column` in `BoardTaskAddOpts` (141) but never reads it; line 189 computes the column from the initial phase for the success message. Header comment line 9 still says "task move — patch task status.column". `runBoardTaskRetry` (506-555) already demonstrates the sanctioned status-phase pattern (with `retryCount` bump for re-dispatch).
- **`packages/manager-controller/src/reconciler/transitions.ts`** — `TRANSITION_TABLE`, `isValidTransition`, `validateTransition`: the single source of truth for allowed `TaskPhase` transitions. Imported by `decision.ts`, `agent/tools.ts` (`set_task_state` validates via it), and two test files. The CLI (`@percussionist/cli` depends only on `api` + `kube`) cannot import it today.
- **`packages/api/src/index.ts`** — `TaskPhase`, `BoardColumn`, `computeBoardColumn` (869-881), legacy `TaskColumn` (884-893), `TaskStatusSchema.column` marked "Legacy column field — kept for backwards compatibility, never written by new code" (1748-1751). `resolveRunConfig` (1886-1928) is the canonical Project→Run default resolver the manager uses (`worker-builder.ts:57` etc.), but it does **not** cover `agent` and the CLI's per-field secret/git merging, so a full swap is riskier than a surgical merge.
- **`README.md`** — line 481 documents `board task move --to <phase>`; lines ~827-831 claim a new task "starts in the 'ready' column" (actually `backlog` via `computeBoardColumn('pending')`).
- **Tests** — `packages/cli/test/` currently has `submit-labels.test.ts` (pure-function tests of `buildRunFromFlags`/`buildRunFromFile`/`withProjectLabels`, no cluster) and `validate.test.ts`. The repo's deterministic-testing culture favors extracting testable pure cores (cf. rev24's `runPollStatusLoop` extraction in dispatcher).

## Approach

Fix each bug at its root, keep changes surgical, and add unit tests at the pure-function level (no cluster required), following the repo's deterministic-principles.

**Bug 1 — merge Project defaults for agent/image/timeout/resources (submit.ts).**
Use the existing `opts.X ?? pd?.X` pattern that the rest of the function already uses:
- `resolvedAgent = opts.agent ?? pd?.agent`
- `image: opts.image ?? pd?.image`
- `timeoutSeconds`: `opts.timeout ? Number(opts.timeout) : pd?.timeoutSeconds` (flag is a string seconds; `pd.timeoutSeconds` is already a number)
- `resources`: add `...(pd?.resources ? { resources: pd.resources } : {})`
- Also inherit `pd.data`, `pd.gitCache`, `pd.runner?.packages` for parity with the manager's `resolveRunConfig` (board runs get them; CLI runs currently don't). These are read-only inheritance like sidecars/initScript — not CLI-overridable.
- Do **not** rewrite the whole function around `resolveRunConfig`: the CLI's per-field secret merging (`opts.llmKeysSecret ?? pd?.secrets?.llmKeysSecret`) and git-source assembly would be regressed by the all-or-nothing `secrets`/`source` precedence in that helper. Note this as a future consolidation.

**Bug 2 — drop the `-n` default; file namespace wins unless `-n` is explicit (index.ts, submit.ts, project.ts).**
- Remove the `DEFAULT_NAMESPACE` third argument from `submit`'s and `project create`'s `-n` options (`index.ts:91`, `index.ts:391`). All downstream code already does `opts.namespace ?? DEFAULT_NAMESPACE`, and `DEFAULT_NAMESPACE` (= kube `NAMESPACE`) honors `$PERCUSSIONIST_NAMESPACE`, which the commander default was silently shadowing.
- With the default gone, `opts.namespace` is only truthy when the user actually passed `-n`; the existing `if (opts.namespace)` guards in `buildRunFromFile`/`buildProjectFromFile` then behave correctly (file preserved, flag wins). No `getOptionValueSource` needed for these two commands once the default is removed — keep it simple; fall back to `cmd.getOptionValueSource('namespace')` only if a default is ever reintroduced.
- Fix the namespace used for the Project-defaults lookup in `runSubmit` with `-f`: pre-parse the file's `metadata.namespace` (YAML is already imported) and compute `ns = opts.namespace ?? fileNs ?? DEFAULT_NAMESPACE` before `getProject`, so `-f` runs without `-n` resolve defaults from the namespace the file will actually land in. `runSubmit`'s final `run.metadata.namespace = run.metadata.namespace ?? ns` (286) already preserves the file's value.

**Bug 3 — 404 handling in `wait` (wait.ts).**
Only take the deleted-mid-wait path (exit 1) when a phase was previously observed; a 404 with no observation is the documented "CR not found" transient → exit 3 with a clear message. To make this testable, extract the polling/decision loop into a pure core that takes an injected `getRun` and returns `{ code, message }`, and make `runWait` a thin wrapper that prints and `process.exit(code)`. This mirrors the repo's extraction-for-testability pattern and keeps the exit-code contract in one testable place. Exit-code mapping stays exactly as documented at `wait.ts:8-13`.

**Bug 4 — dead board surface (board.ts, index.ts, api, README).**
- **Hoist the transition table to `@percussionist/api`** so the CLI can validate against the same source of truth the manager uses: move `TRANSITION_TABLE`, `isValidTransition`, `validateTransition` from `packages/manager-controller/src/reconciler/transitions.ts` into `packages/api/src/index.ts` (next to `computeBoardColumn`), and turn `transitions.ts` into a one-line re-export shim (`export { ... } from '@percussionist/api'`) so all existing imports (`decision.ts`, `agent/tools.ts`, both test files) keep working unchanged. No dependency-cycle risk: api is the base layer and manager-controller already depends on it.
- **Repoint `board task move` to phase transitions**: `--to` now takes a `TaskPhase`; read the task (`getTask`), validate via `validateTransition(currentPhase, to)` (imported from api), and patch `status.phase` only — never `status.column`. On an invalid transition, error with the allowed targets. Add a pure helper (e.g. `resolveTaskMove(currentPhase, to)`) so the validation is unit-testable without the cluster. The command stays a raw phase patch (like the manager's `set_task_state`), and the existing annotation-driven commands (`approve`, `request-changes`, `retry`) remain the preferred path where they apply — `move` is the generic escape hatch.
- **Remove `board task add --column`**: delete the option (`index.ts:493`), the `column` field from `BoardTaskAddOpts` (`board.ts:141`), and the `opts.column` passthrough in the action. New tasks always start `pending` → `backlog`; the success message already computes this at `board.ts:189`.
- Update `board.ts` header comment (line 9), `README.md:481`, and the "starts in the 'ready' column" text (~827-831) → "backlog".

**Bug 5 — `--agent-name` preceding-file semantics (index.ts, submit.ts).**
Implement the documented contract instead of rewriting it away: use a shared accumulator in the `submit` command definition so `--agent-name` binds to the immediately preceding `--agent-file` in argv order, and `--agent-file` becomes a repeatable option collecting `{ path, name? }` entries. A `--agent-name` with no preceding file (or whose preceding file already has a name) is a usage error. Keep the filename-derived-name fallback in `submit.ts`. Update `SubmitOpts`/the loop in `buildRunFromFlags` accordingly. This is a behavior change only for the degenerate orderings that the old index pairing silently misassigned.

**Verification per build**: `pnpm --filter @percussionist/cli test` (bun:test), `pnpm typecheck`, `pnpm lint` (Biome) from the repo root; for the api hoist also run the manager-controller transitions/decision tests. No cluster required for any unit test. Manual smoke (optional, on a dev cluster): `beatctl submit -t x --project p` picks up `p.spec.agent`; `beatctl submit -f run.yaml` with `namespace: my-ns` lands in `my-ns`; `beatctl wait typo` exits 3; `beatctl board task move p --task-name t --to done` rejects an illegal transition and applies a legal one.

### Proposed BUILD task breakdown

Five BUILD tasks, each independently shippable (no cross-dependencies; may run in parallel or via `predecessorRef` ordering):

- **BUILD 1 — submit Project defaults:** Tasks 1-2. `fix(cli): merge project agent/image/timeout/resources defaults into submit` + tests.
- **BUILD 2 — file namespace fidelity:** Tasks 3-5. `fix(cli): stop -n default from overriding file namespaces on submit/project create` + tests.
- **BUILD 3 — wait exit-code contract:** Tasks 6-8. `fix(cli): wait exits 3 on first-poll 404 instead of claiming deletion` (includes the extraction for testability).
- **BUILD 4 — dead board surface:** Tasks 9-12. `fix(cli): repoint board task move to sanctioned phase transitions and drop task add --column` (includes the api transition-table hoist).
- **BUILD 5 — agent-name pairing:** Tasks 13-14. `fix(cli): bind --agent-name to the preceding --agent-file` + tests.

BUILD 4 is the only one touching packages outside `cli` (the api hoist); keep the hoist and the board repoint in the same BUILD so the transition validation change lands atomically with its consumer.

## Risks / open questions

- **`move` is a raw phase patch (BUILD 4).** Moving to phases that require worker metadata (e.g. `running`) can strand a task until the manager's staleness/backoff logic reclaims it. Mitigation: validation against the transition table catches illegal jumps, and the annotation-driven commands (`approve`/`request-changes`/`retry`) remain the documented path for human-in-the-loop moves. If reviewers prefer maximal safety, fall back to **removing** `board task move` and pointing README at the annotation commands — the task explicitly allows either. Flagged as an open question for the reviewer.
- **`resolveRunConfig` vs. hand-rolled merge (BUILD 1).** The canonical helper in `@percussionist/api` is not used by `submit` because of its all-or-nothing `secrets`/`source` precedence. The surgical fix keeps per-field merging; a future BUILD could consolidate the CLI onto `resolveRunConfig` (it would still need a separate `agent` resolution). Noted, not scheduled.
- **Behavior change in `--agent-name` (BUILD 5).** `--agent-name X --agent-file a.md` (name before file) becomes a usage error instead of silently pairing. Acceptable — it never matched the documented contract — but worth a line in the release notes.
- **`$PERCUSSIONIST_NAMESPACE` starts working for `submit`/`project create`** after dropping the commander default (BUILD 2). This is a latent-bug fix, not a regression: the README already documents the env var globally. No script should break unless it relied on the default namespace while the env var pointed elsewhere.
- **First-poll 404 in `wait` (BUILD 3) exits 3 immediately.** A run created slightly after `wait` starts (e.g. racing a `submit --attach`-free flow) will now fail fast instead of spinning. Documented behavior — the CI pattern always submits before waiting, so the CR exists.
- **Open question:** should `board task move --to` accept column names (`backlog`, `in-progress`, …) and map them to phases, for backward compatibility with the current `--to <column>` help? Recommendation: accept phase names only, and print the accepted list on invalid input; README already says `--to <phase>`.

## Acceptance criteria

- `beatctl submit --project p` produces a Run whose `spec.agent`/`image`/`timeoutSeconds`/`resources` come from `p.spec` when no flag overrides them (BUILD 1 tests).
- `beatctl submit -f run.yaml` (no `-n`) preserves the file's `metadata.namespace`, and `beatctl project create -f project.yaml` (no `-n`) preserves the file's namespace; an explicit `-n` still overrides both (BUILD 2 tests).
- `beatctl wait nonexistent-run` exits **3** with a "not found" message; `beatctl wait run-that-was-cancelled` (observed, then deleted) exits **1**; `Succeeded` → 0, other terminal → 1, timeout → 2 (BUILD 3 tests).
- `TRANSITION_TABLE`/`isValidTransition`/`validateTransition` are exported from `@percussionist/api`; manager-controller's `transitions.ts` is a re-export shim and all existing manager tests pass unchanged.
- `beatctl board task move` patches `status.phase` only, rejects illegal transitions with the allowed list, and no longer touches the legacy `status.column`; `--column` on `board task add` no longer exists; README and `board.ts` header comments reflect the phase semantics.
- `--agent-name` binds to the immediately preceding `--agent-file`; a name with no preceding file is a hard error.
- `pnpm typecheck && pnpm test && pnpm lint` pass at the repo root; no cluster-side e2e is required for any of the five fixes.
